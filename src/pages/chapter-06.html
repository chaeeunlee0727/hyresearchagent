Skill을 두 개 만들고 각각 실행까지 해 봤습니다. 마지막 단계는 이 두 Skill을 믿고 반복해서 쓸 수 있는지 같은 기준으로 한 번 점검하는 것입니다. 점검의 결과물은 "다 통과했다"는 표가 아니라 고칠 곳의 목록이고, 그 목록은 이 페이지 안에서 만들어서 수정 요청문으로 바로 이어집니다.

무엇을 점검하나

요약이 맞는지 같은 내용의 검증은 Part 3의 규칙 파일이 맡고 있습니다. 여기서는 실행의 검증만 봅니다. 필요할 때 열리는가, 위험할 때 멈추는가, 같은 입력을 다시 넣어도 안전한가. 이것을 여덟 개 질문으로 쪼갠 것이 아래 점검표입니다. 질문마다 04·05장에서 이미 해 본 시나리오가 근거가 되므로 새로 많이 돌릴 일은 없습니다.

판정 규칙은 하나

근거를 댈 수 없으면 통과가 아니라 보완 필요입니다. "잘 되는 것 같다", "테스트 했음"은 근거가 아닙니다. 어느 시나리오의 어느 결과인지, 어느 파일의 어느 줄인지가 한 줄이라도 적혀야 통과입니다. 애매한 것을 통과로 적기 시작하면 점검표는 다음 Skill부터 작동하지 않습니다.

점검은 세 단계로 끝난다

  1. 자가 점검

    여덟 질문마다 확인할 곳이 적혀 있습니다. SKILL.md와 04·05장 결과를 보고 통과 / 보완 필요 / 해당 없음을 고르고 근거를 한 줄 적습니다.

  2. 교차 점검 (선택)

    자신이 없는 항목은 에이전트에게 같은 여덟 질문을 SKILL.md를 읽고 판정하게 한 뒤 내 판정과 비교합니다. 둘이 다르면 근거를 보고 사람이 정합니다.

  3. 고치고 다시 돌리기

    "보완 필요" 항목만 모아 수정 요청문을 만들고, 고친 뒤 해당 시나리오와 정상 시나리오를 다시 돌립니다. 한쪽을 고치다 다른 쪽이 깨지는 일이 흔합니다.

1Trigger 필요한 요청에서는 열리고, 무관한 요청에서는 조용한가

확인SKILL.md 맨 위 description에 "호출하지 않는 요청"이 적혀 있나. 무관한 요청을 하나 보냈을 때 Skill이 열리지 않았나.

2Input gate 필수 입력이 없으면 아무것도 만들지 않고 묻는가

확인누락 시나리오(두 번째 Skill은 05장 중지 확인)의 판정이 통과였나. 묻고 나서 파일이 하나도 안 생겼나.

3Procedure 규칙 파일과 템플릿을 순서대로 참조하는가. 복사하지는 않는가

4Output contract 정해진 위치·형식을 지키고, 보고가 실제 변경과 같은가

확인정상 시나리오에서 보고한 파일 목록과 git status --short(또는 스냅샷 비교)의 목록이 같았나. 상태값도 보고와 같았나.

5Stop / Ask 추측하기 전에 멈추고, 답을 받기 전까지 아무것도 하지 않는가

확인SKILL.md의 멈춤 조건마다 "답 전까지 하지 않는 행동"이 적혀 있나. 멈춘 시나리오에서 변경 파일이 0개였나.

6Idempotency 같은 입력을 다시 넣어도 중복이 생기지 않는가

확인재실행 시나리오 결과가 변경 0개, log.md 새 줄 없음이었나. 두 번째 Skill은 아직 재실행해 본 적이 없다면 지금 한 번 돌려 보고 판정합니다.

7Scope 내가 정할 판단을 Skill이 대신 채우지 않는가

확인기록에 원인 확정, 우선순위, "추천" 같은 문구가 없나. 05장 ⑥에서 적은 "내 판단" 자리가 비어 있거나 후보로만 적혀 있나.

8Testability 다음에도 같은 테스트를 돌릴 수 있게 요청과 기대 행동이 남아 있는가

확인04장(두 번째 Skill은 05장 A-4)의 요청과 기대 행동이 파일로 남아 있나. 브라우저에만 있으면 내보내기로 저장해야 통과입니다.

6-2. 교차 점검 (선택 · 에이전트에게 · 5분)

자가 점검이 막히거나 내가 너무 후하게 줬는지 의심되면 에이전트에게도 같은 질문을 시킵니다. 지금 선택된 탭의 Skill 이름이 자동으로 들어갑니다. 에이전트의 답을 그대로 따르지 않고 내 판정과 다른 항목만 근거를 보고 다시 정합니다.

.agents/skills/paper-reading/SKILL.md 를 읽고 아래 여덟 기준으로 이 Skill을 점검해줘.
기준: Trigger, Input gate, Procedure, Output contract, Stop / Ask, Idempotency, Scope, Testability

기준마다 통과 / 보완 필요 중 하나를 고르고, 근거로 SKILL.md의 해당 문장을 인용해줘.
인용할 문장이 없으면 통과로 하지 말고 "보완 필요: 해당 규칙이 적혀 있지 않음"이라고 써줘.
보완 필요 항목은 고칠 문장을 한 줄로 제안만 하고, 파일은 고치지 마.

6-3. 고치고 다시 돌리기 (교재에서 만들고 · 에이전트에게 · 8분)

6-1의 각 탭 아래 "수정 요청문 만들기" 버튼을 누르면 "보완 필요"로 표시한 항목과 메모가 요청문으로 묶여 나옵니다. 복사해 에이전트에게 보내고, 제안을 읽고 승인한 뒤, 요청문 아래에 함께 나오는 "다시 확인할 것"대로 시나리오를 다시 돌립니다. 보완 필요가 하나도 없다면 근거 칸이 인상으로 채워지지 않았는지만 다시 봅니다. 그래도 없으면 점검은 끝입니다.

확인할 것

  • 두 Skill 모두 여덟 줄에 판정과 근거 한 줄이 있다
  • 근거 칸에 "했음", "잘 됨" 같은 인상이 없고 시나리오나 파일이 적혀 있다
  • "보완 필요" 항목은 수정 요청문으로 고쳤고, 고친 뒤 해당 시나리오를 다시 돌렸다
  • 수정 후 정상 시나리오도 다시 돌려 한쪽을 고치다 다른 쪽이 깨지지 않았다
  • SKILL.md에서 바뀐 것은 요청문에 적은 항목에 해당하는 문장뿐이다
