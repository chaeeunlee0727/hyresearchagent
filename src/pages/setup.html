SKILL.md는 어디에 두나

Skill 파일은 두 곳 중 하나에 둘 수 있습니다. 사용자 전역 폴더에 두면 어느 프로젝트에서나 열리고, 프로젝트 폴더 안에 두면 그 프로젝트에서만 열립니다. 이 수업의 Skill은 llm_wiki/의 규칙과 템플릿을 참조하므로 그 작업공간에서만 뜻이 있습니다. 그래서 프로젝트 폴더 안의 .agents/skills/<이름>/SKILL.md에 둡니다. Codex와 Hermes 둘 다 이 경로를 프로젝트 전용 Skill로 읽습니다.

세팅 1. 규칙 파일 이름을 AGENTS.md로 맞추기

Part 3 자료는 루트를 CLAUDE.md, 폴더별 규칙을 README.md로 불렀습니다. 이 수업에서는 셋 다 AGENTS.md로 바꿉니다. 이유는 읽히는 방식의 차이입니다.

  • 에이전트는 AGENTS.md를 무조건 읽고 지나갑니다. README.md는 규칙 파일 안에 "반드시 읽어라"고 명시해 둬야 읽히고, 그 안내가 빠지거나 에이전트가 건너뛰면 규칙이 적용되지 않습니다. 이름을 AGENTS.md로 바꾸면 안내 없이도 읽힙니다.
  • 폴더가 여러 층이면 작업 폴더에 가장 가까운 AGENTS.md가 우선합니다. 사용자가 llm_wiki/research/ 안의 작업을 시키면 그 폴더의 AGENTS.md가 먼저, 그다음 상위 폴더 llm_wiki/AGENTS.md, 그다음 루트 AGENTS.md 순으로 적용됩니다. 그래서 폴더별 규칙을 AGENTS.md로 두면 "지금 작업하는 폴더의 규칙이 공통 규칙보다 앞선다"는 구조가 저절로 생깁니다.
  • 이름을 바꿔도 역할은 Part 3과 같습니다. 루트는 공통 원칙, llm_wiki/는 논문 규칙, research/는 프로젝트 규칙입니다.
Part 3 이름이 수업의 이름역할
CLAUDE.mdAGENTS.md공통 원칙. 아래 두 파일을 읽으라는 안내
llm_wiki/README.mdllm_wiki/AGENTS.md논문 페이지·상태·원문 대조·허브 규칙
llm_wiki/research/README.mdllm_wiki/research/AGENTS.md프로젝트·문헌 비교·실험 기록 규칙

이름만 바꾸고 참조를 두면 "llm_wiki/README.md를 따른다"는 문장이 없는 파일을 가리키게 됩니다. 이름과 참조를 함께 고칩니다. 이미 AGENTS.md로 되어 있으면 아래 요청문으로 남은 참조만 확인합니다.

실제 변경은 세팅 3의 통합 요청문 한 번으로 세팅 1~3을 함께 처리합니다. 여기서는 무엇이 왜 바뀌는지만 확인하고 넘어갑니다.

빠진 상태값 하나

Part 4 템플릿의 상태 필드 목록은 metadata_only → summarized → critically_reviewed로 되어 있어 Part 3에서 쓰던 fulltext_available(분석 가능한 원문을 확보함)이 빠져 있습니다. 템플릿을 갱신하다 누락된 것으로 보입니다. 이 값이 없으면 "원문은 구했는데 아직 요약 전"인 페이지를 표시할 자리가 없어지므로, 반영할 때 metadata_only 다음에 다시 넣습니다. 상태 필드 정의 목록과 페이지 상태 종합표 두 곳입니다. 아래 통합 요청문에 이 지시가 들어 있습니다.

차이 목록에서 내가 Part 3 때 직접 바꾼 규칙이 지워지지 않는지 봅니다. 그 부분만 유지하라고 지정한 뒤 나머지를 적용합니다. 이미 만든 프로젝트의 index.md에는 "실험 기록" 절만 추가하고, 프로젝트명이나 연구 질문을 빈 템플릿으로 덮어쓰지 않습니다.

- 복사본 안의 "CLAUDE.md"→"AGENTS.md", "llm_wiki/README.md"→"llm_wiki/AGENTS.md",
  "llm_wiki/research/README.md"→"llm_wiki/research/AGENTS.md",
  ".claude/skills/"→".agents/skills/", "attachments/"→"sources/" 로 바꿔.
  그 외 내용은 바꾸지 마.

세 단계가 끝나면 바뀐 파일 전체 목록과 part4/ 트리를 보여줘.

끝나면 편집기 검색으로 README.md, CLAUDE.md, attachments/가 규칙 파일에 남아 있지 않은지, llm_wiki/AGENTS.md에 fulltext_available이 들어갔는지 직접 봅니다. 에이전트의 "완료" 보고를 그대로 믿지 않고 파일을 열어 보는 습관은 04장 테스트까지 계속 이어집니다.

세팅 4. 구조 확인시키기

통합 요청문이 끝났으면 에이전트에게 작업공간을 실제로 읽게 해 구조를 점검시킵니다. 아직 Skill을 만들거나 논문을 처리하지 않습니다. 없는 파일, 서로 어긋나는 문장, 남아 있는 옛 이름을 지금 잡아 두는 것이 목적입니다.

이 작업공간의 AGENTS.md, llm_wiki/AGENTS.md, llm_wiki/research/AGENTS.md와
llm_wiki 아래 모든 _template.md를 실제로 읽어줘.

확인할 것:
1. 세 규칙 파일이 서로를 가리키는 경로가 모두 실제 파일을 가리키는가
2. CLAUDE.md, README.md라는 문자열이 어디에든 남아 있는가
3. research/_template/ 에 index.md, literature.md, experiment.md, plan.md 네 개가 있는가
4. 루트 AGENTS.md에 "논문을 다룰 때는 llm_wiki/AGENTS.md를, 프로젝트를 다룰 때는
   llm_wiki/research/AGENTS.md도 읽는다"는 뜻의 안내가 있는가
5. .agents/skills/ 폴더가 있는가 (비어 있어도 됨)
6. 원문 폴더 이름이 규칙 파일 전체에서 한 가지(sources/)로 통일되어 있는가
7. llm_wiki/AGENTS.md의 상태 필드에 fulltext_available 이 정의되어 있는가

문제가 있으면 파일과 줄을 적어서 알려주고, 고치지는 마.
논문이나 프로젝트, Skill은 만들지 마.

보고에서 1·2·6·7번에 문제가 없고 3·5번의 파일이 있으면 세팅 끝입니다. 4번 안내가 없으면 루트 AGENTS.md에 두 줄을 직접 추가합니다. 이 안내가 있어야 에이전트가 Skill 없이도 규칙 파일을 찾아 읽고, 03장에서 Skill이 그 규칙을 "복사하지 않고 참조"할 수 있습니다.

여기까지 확인할 것
  • 규칙 파일 세 개의 이름이 모두 AGENTS.md이고 서로 가리키는 경로가 맞는다
  • llm_wiki/AGENTS.md의 상태 필드에 fulltext_available이 다시 들어갔다
  • research/_template/에 experiment.md와 plan.md가 들어왔다
  • part4/에 작업 문서가 있고 참고/는 아직 열지 않았다
  • 기존 논문 페이지와 프로젝트 문서는 바뀌지 않았다 (git을 쓴다면 git status로 확인)
