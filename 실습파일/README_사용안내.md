# Part 04 실습 자료 사용 안내

Part 3의 연구 작업공간을 이어서 사용하며 논문 읽기와 실험 기록 정리를 Skill로 만듭니다.

## 폴더 구성

- `LLM_Wiki_템플릿/`: 기존 Wiki에 갱신·추가하는 파일 5개입니다.
- `실행계약_템플릿.md`: 새 Skill의 입력, 처리, 출력, 중단 조건과 검증 기준을 정리하는 양식입니다.
- `paper-reading/`: 생성 프롬프트, 실행 계약, 완성된 `SKILL.md`와 테스트 기록 양식·작성 예시입니다.
- `experiment-log/`: 생성·실행 프롬프트, 실행 계약과 완성된 `SKILL.md`입니다.
- `공통/`: Skill 후보 선정과 품질 점검에 사용하는 표와 체크리스트입니다.

## Part 3에서 갱신하는 파일

**Part 3의 작업공간을 먼저 준비합니다.** 새로 시작한다면 Part 3의 `LLM_Wiki_템플릿/`으로 초기화한 뒤 아래 변경을 적용합니다. 경로는 모두 `CLAUDE.md`가 있는 작업공간 루트 기준입니다. 이 폴더의 `LLM_Wiki_템플릿/` 아래 상대 경로와 적용 위치가 같습니다.

| 적용 위치 | 구분 | 변경 내용 |
|---|---|---|
| `llm_wiki/README.md` | 갱신 | 파일명, 서지·원문 확인 상태, 허브 등록 범위, 개념 페이지 생성 조건, PDF 사본 보관 규칙을 구체화합니다. |
| `llm_wiki/research/README.md` | 갱신 | 실험 기록·후보표의 저장 위치, 원본 불변, baseline 누락 시 중지와 프로젝트 초기화 방법을 추가합니다. |
| `llm_wiki/research/_template/index.md` | 갱신 | 프로젝트의 실험 기록 목록을 추가합니다. |
| `llm_wiki/research/_template/experiment.md` | 추가 | `experiment-log`가 참조하는 실험 기록 양식입니다. |
| `llm_wiki/research/_template/plan.md` | 추가 | 실험 후보의 근거와 우선순위를 비교하는 양식입니다. |

`CLAUDE.md`, 논문·개념 템플릿, `literature.md` 템플릿과 허브·index·log는 Part 3에서 계속 사용합니다. 이 Part의 폴더로 작업공간 전체를 교체하지 않습니다.

Claude에게 위 파일과 현재 작업공간을 대조해 **변경 목록을 먼저 보여 달라고 요청합니다.** 직접 수정한 규칙은 차이를 확인한 뒤 반영합니다. 기존 논문, 연구 질문, Literature Matrix, 실험 결과와 `log.md` 기록은 유지합니다.

기존 `llm_wiki/index.md`에 `research/_template/ 전체를 복사`한다는 안내가 남아 있으면, 그 문장만 다음 안내로 갱신합니다. 기존 논문·허브·프로젝트 목록은 유지합니다.

```markdown
새 프로젝트 생성은 `research/README.md`의 절차를 따릅니다.
```

이미 만든 프로젝트의 `index.md`에는 실험 기록 목록만 추가합니다. 프로젝트명·질문·자원·기존 링크를 빈 템플릿으로 덮어쓰지 않습니다. 문헌이 부족하면 기존 `literature.md`에 추가 확인 범위를 기록할 절을 마련합니다.

새 프로젝트는 Claude가 공용 `_template/index.md`와 `_template/literature.md`로 초기화합니다. `experiment.md`와 `plan.md`는 공용 `_template/`에 두고 실제 기록·계획이 생길 때 각각 `experiments/`와 `plans/` 아래 문서를 만드는 데 사용합니다. 프로젝트 루트에 빈 실험·계획 파일을 미리 복사하지 않습니다.

### Wiki 처리 규칙의 변화

| 항목 | Part 4에서 적용하는 규칙 |
|---|---|
| 원문 미확보 | 서지가 확인됐으면 `metadata_only / unreviewed`로 남깁니다. 원문 추출 실패는 `needs_review / needs_review`로 구분합니다. |
| `fulltext_available` | 별도 완료 상태로 사용하지 않습니다. 이전 페이지는 실제 요약·검증 진행 상태와 원문을 확인한 뒤 상태를 갱신합니다. 상태명만 일괄 치환하지 않습니다. |
| 논문 파일명 | 제목의 핵심 단어로 파일명을 정합니다. 연도·제1저자 중 한 값이 공식 자료에 없으면 자리표시자를 사용하고 둘 다 확인되지 않으면 식별 정보를 요청합니다. 일괄 이름·링크 변경에는 승인이 필요합니다. |
| 허브·개념 연결 | 서지 단계에서는 확인된 저자·연도·venue에만 연결합니다. 개념은 요약 이후 원문에서 정의를 확인한 경우에 생성합니다. |
| PDF | `attachments/`에 사본을 두고 `source_file`로 연결합니다. 미식별 PDF는 `attachments/_unidentified/`에 보관하고 식별 후 정식 위치로 옮깁니다. |

## Skill 생성 또는 등록

직접 만들 때는 실행 계약을 작업공간 루트의 `paper-reading_실행계약.md` 또는 `experiment-log_실행계약.md`로 준비한 뒤 해당 생성 프롬프트를 사용합니다. 생성 결과와 완성된 Skill을 비교하고 계약의 내용이 반영됐는지 확인한 뒤 Claude에게 작업용 계약 파일 정리를 요청합니다.

완성된 Skill로 시작할 때는 Claude에게 다음 위치에 등록해 달라고 요청합니다. 직접 생성한 Skill이 이미 있으면 두 파일의 차이를 검토하고 하나의 `SKILL.md`에 반영합니다.

| 이 폴더의 파일 | 작업공간에 등록할 위치 |
|---|---|
| `paper-reading/SKILL.md` | `.claude/skills/paper-reading/SKILL.md` |
| `experiment-log/SKILL.md` | `.claude/skills/experiment-log/SKILL.md` |

생성 프롬프트, 실행 계약과 테스트 양식은 필요할 때 Claude에게 지정하는 작업 문서입니다. 이 파일들을 `.claude/skills/`에 함께 등록하지 않습니다.

### 실행 계약에서 Skill로 이어지는 변경

계약을 설계한 뒤 Skill을 완성하는 과정에서 다음 규칙을 보완합니다. 이 폴더의 실행 계약에도 아래 내용을 반영했습니다. 이전에 작성한 계약·Skill이 있으면 같은 기준으로 갱신합니다.

| 대상 | 이전 계약에서 보완할 내용 | 현재 적용 내용 |
|---|---|---|
| `paper-reading` | 서지 확정 전 PDF 저장 보류 | 미식별 사본을 보관하고 위치를 보고합니다. 논문 페이지 생성과 구분합니다. |
| `paper-reading` | 개념은 기존 페이지에만 연결 | Wiki의 개념 생성 조건을 충족하면 생성합니다. 생성 규칙이 없는 페이지는 만들거나 링크하지 않습니다. |
| `experiment-log` | baseline 원본이 없으면 비교만 생략하고 진행 | baseline 기록·원본이 모두 없으면 확인을 요청하고 중지합니다. 평가 조건이 다른 경우의 비교 보류와 구분합니다. |
| `experiment-log` | 프로젝트 index 갱신 | index와 함께 `llm_wiki/log.md`에 요청 단위 변경 기록을 남깁니다. |

## 실행 결과 확인

자신의 논문과 연구 기록으로 실행한 뒤 파일, 상태, 근거, 링크와 완료 보고를 확인합니다. 같은 입력을 다시 처리했을 때 페이지와 index 항목이 중복되지 않는지도 확인합니다.

`paper-reading/테스트_기록표.md`는 점검을 기록할 때 선택해서 사용합니다. `테스트_기록_완성예시.md`는 작성 방식의 예시입니다. 자신의 실행 결과로 통과·보완 여부를 판단합니다.

## 활용 범위

제공된 템플릿과 Skill은 하나의 예시입니다. 연구자분들의 선호, 연구 환경과 필요에 따라 절차를 더 복잡하게 만들거나 단계를 줄일 수 있습니다. 입력과 출력 형식을 다양하게 추가하거나 검증 기준을 더 자세히 정할 수도 있습니다. 변경할 때는 입력 파일, 처리 순서, 중단 조건과 결과 파일이 서로 맞는지 함께 확인해 보시면 좋습니다.
