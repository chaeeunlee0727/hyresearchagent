# research 운영 규칙

연구 프로젝트는 `research/<프로젝트명>/` 폴더 하나씩이다. 프로젝트 안의
문헌 검토(literature.md), 실험 계획과 로그, 원고, 결과물은 항상 OKF 페이지로
남긴다. 실험에 사용되는 코드나 데이터는 예외로 둔다.

논문 페이지 자체의 규칙은 `llm_wiki/README.md`가 정한다. 이 문서는 프로젝트
문서와 Literature Matrix의 규칙만 정한다.

## 새 연구 프로젝트 생성

연구 아이디어와 초기 질문이 합의되기 전에는 프로젝트 폴더를 만들지 않는다.

사용자가 새 프로젝트 시작을 요청하면:

1. 연구 아이디어를 확인하고 프로젝트명, 초기 연구 질문, 포함 범위를 제안한다.
2. 사용 가능한 데이터, 연산 자원, 기간, 장비, 인력과 필수 제약을 물어 확인한다.
3. 사용자 승인을 기다린다.
4. 승인 후 프로젝트 폴더를 만들고 `_template/index.md`와 `_template/literature.md`를 복사한다. 실험·계획 템플릿은 공용 `_template/`에 유지하고, 실제 작업 때 `experiments/<run_id>.md`와 `plans/`의 후보표를 만드는 데 사용한다.
5. 복사한 `index.md`의 제목을 프로젝트명으로 바꾸고, 연구 아이디어, 초기 연구
   질문, 연구 상태, 연구 자원과 제약을 인터뷰에서 확인한 내용으로 채운다.
6. 복사한 `literature.md`의 제목·프로젝트 메타데이터와 본문의 연구 질문을 채운다.
7. 프로젝트 초기화 중에는 공용 템플릿을 임의로 수정하지 않는다. 템플릿 변경 요청은 별도 작업으로 처리한다.
8. 생성 사실과 초기 상태를 `llm_wiki/log.md`에 기록한다.

연구 자원과 제약은 추측해서 채우지 않는다. 사용자에게 물어 확인한 내용만
기록한다. 이후 실행 가능성 평가는 이 기록을 읽어 수행하고, 정보가 없으면
평가를 멈추고 사용자에게 묻는다.

## 관련 문헌 선별

프로젝트의 질문과 포함·제외 기준을 기준으로 현재 Wiki 전체에서 후보를 제안한다.
후보 탐색에는 주제·저자·연도·venue 허브를 사용하되, 비교값과 근거는 반드시
연결된 실제 논문 페이지에서 가져온다. 허브의 짧은 설명만으로 판단하지 않는다.

후보마다 다음을 표시한다.

- 관련성 근거
- `processing_status` / `evidence_status`
- 포함 또는 제외 제안
- 분석에 쓸 수 없는 경우의 정확한 상태와 사유

## Literature Matrix

Matrix는 프로젝트 폴더가 생성된 뒤에만 채운다. 프로젝트의 `literature.md`에
연구 질문과 포함·제외 기준을 먼저 채우고, 그 기준으로 선별한 논문을 행으로 넣는다.

- 열은 표를 만드는 시점에 프로젝트 질문에 맞게 구성한다. 논문, 주요 결과,
  제한 조건, 처리 상태, 근거 상태, 원문 근거를 공통 필드로 두고, 연구 질문의
  성립 여부를 판별하는 비교 축을 열로 추가한다. 템플릿이나 다른 프로젝트의
  열 구성을 그대로 가져오지 않는다.
- 원문 미확보·추출 실패: 관련성 후보로는 남기되 분석 행에서 제외하고, 실패 사유와 다음 조치를 연결한다.
- `summarized / unreviewed`: 요약 필드를 쓸 수 있으나 검증 전임을 표시한다.
- `critically_reviewed / verified`: 원문 근거와 제한 조건까지 비교에 사용한다.
- `needs_review`: 관련성만 기록하고 근거가 필요한 필드는 비워 확인 목록으로 보낸다.

빈칸을 다른 논문의 내용으로 채우지 않는다. 서로 다른 데이터셋과 지표의 숫자를
같은 조건의 성능처럼 비교하지 않는다.

## 문헌이 부족할 때

관련 논문이 부족해도 내용을 추정해 Matrix를 채우지 않는다.
`literature.md`에 `추가로 확인이 필요한 논문` 절을 마련하고 부족한 범위를 남긴다. 이미 해당 절이 있으면 이어서 갱신한다.

## 실험 기록

구조화된 실험 기록은 해당 프로젝트의 `experiments/<run_id>.md`에 둔다.
페이지 형식은 `_template/experiment.md`를 따른다. 원본 로그, config, 결과
파일은 읽기만 하고 수정하지 않는다.

프로젝트 `index.md`의 실험 기록 목록을 갱신한다. 실패 원인 확정, 다음 실험
선택, 실험 실행은 이 문서의 범위가 아니다.

대비 계산은 평가 데이터셋, split, 클래스, 마스크 규칙이 같은 기록끼리만 한다.
baseline이 지정됐는데 구조화된 기록이 없고, 같은 요청에 그 원본도 없으면
비교만 빼고 진행하지 않는다. baseline부터 기록할지 묻고 중지한다.

## 실험 계획(후보표)

다음 실험 후보의 비교와 순위는 해당 프로젝트의 `plans/` 아래 페이지로 남긴다.
페이지 형식은 `_template/plan.md`를 따르고, 템플릿에 없는 항목을 새로 만들지 않는다.

- 기록·문헌에서 확인한 값은 `[기록]`, 후보표가 근거를 밝혀 채운 값은 `[제안]`,
  근거가 없으면 `(확인 필요)`로 구분한다.
- 모든 후보는 `승인 대기`로 시작한다. 채택과 실행 승인은 연구자가 한다.
- 생성·갱신하면 프로젝트 `index.md`의 관련 목록을 갱신한다. `llm_wiki/log.md`
  기록은 위임이 끝난 뒤 메인 대화가 남긴다.
