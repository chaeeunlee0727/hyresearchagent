# paper-reading 실행 계약

논문 한 편을 LLM Wiki에 넣는 반복 절차의 실행 계약.
요약 형식과 검증 규칙은 `llm_wiki/papers/_template.md`, `llm_wiki/README.md`,
`llm_wiki/research/README.md`가 정한 대로 따른다. 여기서는 실행 조건과
상태 전이만 정한다.

이 문서의 모든 상대 경로는 `CLAUDE.md`가 있는 작업공간 루트를 기준으로 한다.

## Trigger

- 새 논문을 Wiki에 추가해 달라는 요청
- 기존 논문 페이지의 보완이나 상태 진행 요청
- 논문 추가에 따른 관련 연구 프로젝트 갱신 요청
- 호출하지 않는 경우: 논문 내용에 관한 단순 질문, Wiki 구조 변경 요청,
  논문 추가 없이 프로젝트 문서만 정리하는 요청. 뒤의 것은
  `llm_wiki/research/README.md`를 직접 따른다
- 호출 여부가 모호한 요청은 Wiki 파일이나 상태를 바꾸려는지 물어보고 시작한다
- 논문 근거를 다시 확인해 달라는 요청은 먼저 답변으로 처리한다. 확인 결과
  페이지 내용이나 상태를 고쳐야 하면 그때 이 Skill을 호출한다
- 논문 파일명 규칙을 바로잡아 달라는 요청에도 호출한다. 파일명만 바꾸지 않고
  연결된 링크와 index를 함께 고친다
- 여러 논문 파일명을 한꺼번에 정정할 때는 전체 rename·링크 변경 목록을 먼저
  제시하고 사용자 승인 후 적용한다

## Input

- 필수: 논문을 식별할 수 있는 식별·서지 정보
  (DOI, arXiv ID, 공식 URL, 제목+공식 공개 페이지).
  사용자가 원문 파일을 직접 줄 수도 있다.
- 받은 값은 외부 서지 DB에서 대조해 확정한다. 대조되지 않으면 확정하지 않고
  Stop / Ask로 넘긴다. 사용자가 준 값을 그대로 믿고 페이지를 만들지 않는다.
- DB에 해당 논문이 없는 경우와 DB에 접근하지 못한 경우를 구분한다. 접근 실패는
  식별 실패로 처리하지 않고 접근하지 못했다는 사실을 밝히고 중지한다.
- 선택: 연결할 기존 연구 프로젝트, 비교하고 싶은 질문, 특별히 주의 깊게 볼 부분.
  없어도 진행한다.
- 제목만 받으면 외부 서지 DB에서 찾는다. 단일 후보로 확정되면 진행하고,
  후보가 여럿이면 어느 논문인지 묻는다.
- 원문은 필수 입력에 넣지 않는다. 원문 확보 여부는 아래 상태 전이에서 판정하고
  확보에 실패해도 확인된 서지까지는 기록한다.
- 사용자가 원문 PDF를 제공하면 `llm_wiki/README.md`의 원문 파일 규칙에 따라
  `llm_wiki/attachments/`에 사본을 저장하고 `source_file`에 상대 위치를 기록한다.
  서지를 확정하지 못해 페이지를 만들지 않는 경우에도 받은 PDF는
  `llm_wiki/attachments/_unidentified/`에 보관하고 경로를 질문과 완료 보고에 적는다.
  서지를 확정하면 같은 작업에서 페이지 파일명 줄기로 옮기고 `source_file`을 기록한다.
  별도 식별자가 없으면 PDF에서 제목·저자·연도를 먼저 읽은 뒤 외부 서지 DB에서
  대조한다.

## Process

1. 식별·중복 검사: 식별 정보로 메타데이터를 외부 서지 DB에서 확인하고
   기존 페이지와의 중복을 검사한다. 기존 페이지가 있으면 새로 만들지 않고
   새 정보가 있는 부분만 갱신하고, 새 정보가 없으면 건너뛴다.
2. 원문 확보 판정: 합법적으로 접근 가능한 원문을 찾는다.
3. 도달 가능한 상태까지 저장하고 상태와 링크, index, log를 갱신한다.
   상세 절차와 상태 값의 정의는 `llm_wiki/README.md`를 따른다.
4. 프로젝트 갱신은 지정된 프로젝트만 수행한다.

원문을 정상적으로 확보하면 한 호출에서 Summary와 원문 대조 검증까지 이어서
수행한다. 이때도 중간 상태 `summarized / unreviewed`를 기록한 뒤 최종 상태로
갱신한다. 사용자가 "요약까지만", "검증은 하지 마"처럼 명시한 경우에만 검증을
건너뛰고 남은 단계를 완료 보고에 적는다. "간단히 정리", "빠르게 봐줘"처럼
범위가 불분명한 표현은 검증 생략으로 해석하지 않는다. 같은 답을 다시 생성한 것은
검증으로 인정하지 않는다. 표시한 원문 위치의 재확인만 검증으로 본다.

여러 편을 한 번에 요청받으면 이 계약을 논문별로 한 번씩 순차 적용한다. 한 편의
중지 사유가 다른 논문의 처리를 막지 않게 한다. 공용 허브와 index는 모든 논문
처리가 끝난 뒤 한 번 갱신하고 `log.md`에는 요청 단위로 한 건만 기록한다. 최종
보고에는 논문별 상태와 생성·수정·중지 결과를 나누어 적는다.

## Output

### 도달한 상태별로 남기는 것

처리가 어디에서 끝나든 도달한 상태를 저장하고 종료한다. 상태 값의 정의는
`llm_wiki/README.md`를 따른다.

- 연도·제1저자 중 한 값을 확인하지 못하면 README의 자리표시자 규칙으로 파일명을
  만들고 `needs_review / unreviewed`로 남긴다.
- 서지를 외부 DB에서 확인하지 못하면 논문 페이지를 만들지 않고 Stop / Ask로 묻는다.
  받은 PDF는 원문 파일 규칙에 따라 `_unidentified/`에 보관한다.
- 원문을 확보하지 못하면 확인된 서지와 실패 사유까지만 기록하고
  `metadata_only / unreviewed`로 남긴다. 추정 금지 범위는
  `llm_wiki/README.md`의 자동 중단 조건 절을 따른다.
- 원문을 확보했으나 읽거나 텍스트로 추출하지 못하면 사유를 기록하고
  `needs_review / needs_review`로 남긴다.
- Summary까지 마치면 `summarized / unreviewed`, 원문 대조까지 마치면
  `critically_reviewed / verified` 또는 `partial`·`unsupported`·`needs_review`에
  맞는 조합으로 갱신한다.
- `needs_review / partial`은 도달 상태로 인정하고 여기서 종료한다.
- `needs_review / unsupported`는 해당 판단을 확정 내용에서 제외하고 검토 목록으로
  옮긴다.

### 갱신 범위

- 새 논문 페이지 또는 기존 페이지의 갱신. 위치는 `llm_wiki/papers/` 아래
  한 편당 한 파일이고, 파일명 규칙과 형식은 `llm_wiki/README.md`와
  `papers/_template.md`를 따른다.
- 허브 등록 범위는 `llm_wiki/README.md`의 추가 절차 절을 따른다. `metadata_only`
  페이지와 부분 식별·추출 실패로 `needs_review`가 된 페이지가 여기 해당한다.
- 자동 생성하는 파생 페이지는 `llm_wiki/README.md`에 생성 규칙이 명시된 허브,
  index와 개념 페이지로 제한한다. topics/ · venues/ · years/ · authors/와 concepts/가
  해당한다. 개념은 요약 이후 원문에서 정의를 확인하고 README의 생성 조건을 충족할 때만 만든다.
- README에 생성 규칙이 없는 허브나 페이지는 이 계약으로 만들거나 링크하지 않는다.
  정의를 확인하지 못한 개념은 논문 페이지의 Open questions와 완료 보고에 남긴다.
- 프로젝트를 지정하지 않으면 공통 허브·index·log까지만 갱신하고 프로젝트 문서는
  건드리지 않는다. 지정하면 그 프로젝트의 `literature.md`와 관련 링크만 갱신한다.
- `log.md`에 변경 기록을 남긴다.

### 완료 보고

- 생성한 파일, 수정한 파일, 건너뛴 항목과 이유, 사람 확인이 필요한 항목을
  파일 경로와 함께 보고한다.
- 도달한 `processing_status` / `evidence_status`와 그렇게 판정한 근거를 밝힌다.
- `needs_review / partial`과 `needs_review / unsupported`는 실패로 보고하지 않는다.
  "자동 처리 완료, 사람 확인 필요"로 구분해 보고한다.
- 원문 PDF 사본을 저장하거나 기존 사본을 재사용했다면 그 경로를 밝힌다.
  `_unidentified/`에 보관 중인 사본도 경로를 밝힌다.
- 선택 입력이 없어 생략한 작업(예: 프로젝트 갱신)을 표시한다.

## Stop / Ask

아래와 같은 경우 답을 받기 전에는 Wiki 페이지를 만들거나 고치지 않는다.
사용자가 준 원문 PDF를 `_unidentified/`에 보관하는 것은 허용한다.
여러 편을 함께 처리할 때 이 규칙은 해당 논문 한 편에만 적용한다.
나머지 논문은 계속 처리하고, 물어야 할 것은 모아서 묻는다. 묻는 시점은
공용 허브와 index 갱신, 완료 보고까지 끝낸 다음이다.


- 논문을 식별하지 못했을 때. 어떤 논문인지 묻는다. 논문 페이지는 만들지 않는다.
- 기존 페이지와의 중복 여부가 모호할 때. 새 페이지를 만들지 않고 묻는다.
- 프로젝트 갱신 요청의 대상이 모호할 때. 새 프로젝트를 만들지 않고 묻는다.
- 새 프로젝트 생성과 논문 추가를 함께 요청받았을 때. 논문은 공통 Wiki까지
  처리한다. 프로젝트 생성과 연결은 `llm_wiki/research/README.md`의 승인 절차를
  안내한 뒤 승인 전에는 수행하지 않는다.

나머지 중지는 묻지 않고 도달한 상태를 저장한 뒤 종료한다. 어떤 상태로 남는지는
Output을 따른다. 프로젝트 지정이 없는 단순 논문 추가는 중지 사유가 아니다.

## Validation

- 같은 논문의 페이지, 허브 항목, 상호 링크와 `log.md` 항목이 중복되지 않았는지
  확인한다.
- `processing_status` / `evidence_status`가 실제로 도달한 처리 단계와 일치하는지
  확인한다.
- 프로젝트가 지정되지 않았다면 프로젝트 문서가 변경되지 않았는지 확인한다.
- `index.md`, `log.md`, 허브·링크와 완료 보고를 실제 생성·수정 파일과 대조한다.
