# experiment-log

## Overview

비정형 실험 로그를 구조화된 기록으로 바꾸는 절차의 실행 계약이다. 그 기록은 다음
판단에 사용할 수 있다. `paper-reading` 실행 계약과 같은 틀을 쓴다.

**실패 원인 확정, 다음 실험의 우선순위 결정, 실험 실행과 승인은 이 계약 밖에 있다.**

이 문서의 모든 상대 경로는 `CLAUDE.md`가 있는 작업공간 루트를 기준으로 한다.

| 참조 문서 | 이 문서가 위임하는 것 |
|---|---|
| `llm_wiki/research/README.md` | 실험 기록의 저장 위치, 프로젝트 `index.md` 갱신 범위, 원본 불변 규칙 |
| `llm_wiki/research/_template/experiment.md` | 페이지 형식(표 구성, 섹션, 필드) |

페이지 형식과 저장 위치는 위 두 문서를 따르고, 여기서 다시 정하지 않는다.

## 호출 조건

호출한다.

- 실험 종료 후 로그 정리 요청
- 여러 실험 결과를 비교하기 전 기록 표준화 요청

호출하지 않는다.

- 실험 실행 요청
- 다음 실험을 골라 달라는 요청

## 입력

**필수** — 원본 로그(메모, 터미널 출력 등)와 실험 식별 정보(run ID 또는 날짜+대상).

**선택** — config 파일, 결과 표, 연구자 메모, 비교할 baseline 실험.

입력의 사실 원천은 다음과 같이 구분한다.

| 값의 종류 | 사실 원천 |
|---|---|
| 설정값 | config |
| 측정값 | 결과 표 |
| 목적 · 관찰 · 가설 | 연구자 메모 |

**서로 다른 원천의 값이 충돌하면 우선순위로 덮어쓰지 않고 중지한다.**

baseline은 사용자가 직접 지정한 경우 외에도 config의 baseline 참조 필드나 메모의
비교 서술로 확인되면 지정된 것으로 본다.

## 절차

1. **입력을 검사하고 실험을 식별한다.** 프로젝트, 과제, 데이터셋, 평가 split과 기존
   기록의 실험 ID 중복을 확인한다. 같은 ID의 기록이 이미 있으면 새로 만들지 않고
   변경분만 갱신한다.
2. **baseline이 지정되면 구조화된 baseline 기록이 있는지 먼저 확인한다.** 기록이 없고
   원본을 찾을 수 있으면 baseline을 먼저 구조화한 뒤 대상 실험을 처리한다. 기록이 없고
   같은 요청에 그 원본도 없으면 **비교만 빼고 진행하지 않는다.** baseline부터 기록할지
   묻고 중지한다. 여러 실험을 함께 받으면 이 의존 순서대로 하나씩 처리한다.
3. **원본에서 목적, 변경 변수, 유지 조건, 결과를 추출한다.** 각 값에 원본 파일과
   위치를 근거로 남긴다.
4. **평가 데이터셋과 split, 클래스, 마스크 규칙이 baseline과 같다고 원본에서 확인될
   때만 대비를 계산한다.** 조건이 다르거나 원본에 조건이 적혀 있지 않으면 그 지표의
   대비 칸을 확인 필요로 남기고 나머지 기록은 그대로 진행한다. 연구자가 메모에 이미
   적어 둔 대비 수치는 관찰 칸에 연구자 서술로 옮기고 대비 칸으로 옮기지 않는다.
5. **관찰된 사실과 실패 원인 후보를 분리하고** 후보마다 확인 방법을 적는다.
6. **다음 실험 후보를 승인 대기 상태로 정리한다.** 우선순위를 매기거나 실행하지
   않는다. 원본에 후보가 없거나 후보를 만들지 않는다고 적혀 있으면 후보를 만들지 않고
   `없음`과 그 근거 위치를 남긴다.
7. **구조화된 기록을 해당 연구 프로젝트의 `experiments/`에 저장하고** 프로젝트
   `index.md`의 실험 기록 목록을 갱신한다. `llm_wiki/log.md`에 변경 기록을 남긴다.
   여러 실험을 한 요청으로 처리하면 요청 단위로 한 건만 기록한다.

## 산출물

**구조화된 실험 기록** — 실험 ID, 목적, 변경 변수, 유지 조건, 주요 지표,
평가 데이터셋·split, baseline 대비 변화, 관찰, 근거 위치, 확인 필요 항목.

**실패 원인 후보** — 설명이 필요한 관찰을 먼저 지목하고 그 하나에 원인 후보를 여러 개
붙인다. 확인 방법은 후보마다 하나씩 적는다. 원본에서 이미 확인된 관찰은 후보를
만들지 않는다.

**승인 대기 상태의 다음 실험 후보** — 확인 목적, 변경 변수, 유지 조건, 기대 관찰,
성공 기준, 리스크와 필요한 승인.

위 항목 중 원본에서 확인하지 못한 필드는 추정해 채우지 않고 확인 필요 항목으로 남긴다.

**저장 위치** — `llm_wiki/research/<프로젝트>/experiments/<run_id>.md`

## 완료 보고

- 생성·수정 파일
- 갱신한 index와 `log.md`
- 원본에서 확인하지 못한 값
- 사람 확인 항목

## 중지와 질문

- 실험 ID가 기존 기록과 충돌하는데 같은 실험인지 판단할 수 없을 때
- 핵심 설정(변경 변수, 데이터셋 등)을 어떤 입력에서도 찾을 수 없을 때
- 결과 표의 수치와 로그의 서술이 서로 다를 때
- 저장할 연구 프로젝트를 정할 수 없을 때
- baseline이 지정됐는데 구조화된 기록이 없고 같은 요청에 그 원본도 없을 때.
  baseline부터 기록할지 묻는다. 비교만 빼고 진행하지 않는다

## 마지막 점검

- 결과 표의 수치, 메모의 서술, 기록에 적은 값이 서로 일치하는지 확인한다.
- 기록의 모든 수치와 판단에 원본 파일과 위치가 붙어 있는지 확인한다.
- baseline 대비를 계산한 지표가 평가 조건을 확인한 지표뿐인지 확인한다.
- 같은 실험 ID의 기록, index 항목, `log.md` 항목이 중복되지 않았는지 확인한다.
- 완료 보고 항목을 실제로 생성·수정한 파일과 대조한다.

## 원본 불변

원본 로그, config, 결과 파일은 읽기만 하고 수정하거나 삭제하지 않는다.
구조화 결과는 항상 별도 파일로 저장한다.
