# llm_wiki 운영 규칙

## 추가 절차

에이전트는 식별자(DOI·arXiv ID·URL)나 서지 정보로부터 논문의 원문을 찾아 llm_wiki에 추가한다.
llm_wiki의 모든 markdown 페이지는 Open Knowledge Format을 따르며, 각 논문의 topic, venue,
year, author 정보는 각각 topics/, venues/, years/, authors/ 아래에 페이지를 만들어 링크를
걸어둔다. 새로운 정보가 추가될 때에는 연관되어 있는 index.md 파일들을 갱신하고, log.md에
수정된 내용에 대한 기록을 남긴다.

`metadata_only` 페이지는 `llm_wiki/index.md`와 확인된 저자·연도·venue 허브에
등록한다. topic 허브 연결은 원문을 확보해 내용을 확인할 때까지 보류한다.

부분 식별이나 원문 추출 실패로 `needs_review`가 된 페이지도
`llm_wiki/index.md`와 확인된 저자·연도·venue 허브에만 등록한다. 확인하지 못한
허브와 topic 연결은 사람 확인 전까지 보류한다.

## 서지 확정

내보내기 파일(.ris·.bib)의 값을 그대로 믿지 않는다. 저자·연도·게재처·DOI는 최소 한 곳의
외부 서지 DB(Crossref, arXiv, DataCite, 발행처 공식 아카이브)에서 대조한 뒤 확정한다.
대조로 값이 바뀌었으면 무엇을 어떻게 고쳤는지 해당 페이지에 남긴다.

내보내기 원본 파일은 수정하지 않는다. 정정 결과는 위키 페이지에만 반영한다.

## 식별자

DOI는 기록하기 전에 실제로 해석되는지 확인한다. 해석되지 않는 DOI는 `doi` 필드에 넣지 않고,
주장된 값과 확인된 서지만 본문에 적는다. 원문 확보 여부와 관계없이 Summary를 작성하기 전에
`processing_status: needs_review`, `evidence_status: needs_review`로 멈춘다.

발행처가 DOI를 발급하지 않는 경우(arXiv 전용, NeurIPS, CVF 워크숍 등)에는 arXiv DOI 또는
발행처 공식 공개 URL을 식별자로 쓴다. DOI가 없다는 사실 자체는 중단 사유가 아니다.

## 대표판과 중복

같은 연구가 프리프린트와 정식 게재본으로 함께 있으면 정식 게재본을 대표로 삼는다. 파일명의
연도와 `year`는 정식 게재본 기준이고, 프리프린트는 `arxiv_id`와 `preprint_year`(DOI가 있으면
`preprint_doi`)에 남긴다.

같은 논문이 여러 레코드로 들어오면 한 페이지로 병합하고, 병합한 레코드 목록을 Citation 절에
남긴다.

논문 사이의 서지 관계(확장판, 프리프린트, 병합)는 Citation 절에 적고 양쪽 페이지에서 서로
링크한다.

## 일괄 이관

여러 편을 한 번에 이관할 때는 논문 페이지를 먼저 모두 만들고, topics/·venues/·years/·authors/
허브 페이지와 각 index.md는 마지막에 한 번에 생성한다. 논문마다 허브를 갱신하면 같은 파일을
여러 번 고치게 된다. log.md에는 이관 단위로 한 건만 기록한다.

## 페이지 형식

- 논문 페이지 파일명은 `연도_저자_키워드.md`
- `키워드`는 공식 영문 제목에서 관사·전치사 등 불용어를 뺀 뒤, 앞의 핵심 단어
  세 개를 소문자 하이픈으로 연결한다. 공식 영문 제목이 없으면 원제에서 불용어를
  뺀 앞의 핵심 단어 세 개를 원문 문자 그대로 하이픈으로 연결한다. 같은 논문을
  다시 처리할 때도 이 규칙을 적용해 파일명이 달라지지 않게 한다
- `_template.md`를 작업 파일로 쓰지 않는다. 항상 복사해 새 파일을 만든다. 프런트매터
  필드를 늘려야 하면 `_template.md`에 먼저 추가하고, 페이지에만 있는 필드를 만들지 않는다
- 템플릿에 없는 섹션을 새로 만들지 않는다. 채울 내용이 없으면 제목만 두고 비운다
- 저자 파일명은 `이름-성`을 소문자·하이픈으로 쓰고, 비ASCII 문자는 ASCII로 옮기며
  (Björn Ommer → `bjorn-ommer`), 중간 이니셜의 마침표는 뺀다
  (Anil S. Baslamisli → `anil-s-baslamisli`)
- 같은 저자 페이지가 이미 있으면 새로 만들지 않고 기존 페이지의 Papers 목록에 추가한다.
  동명이인 여부가 불확실하면 합치지 말고 `needs_review`로 남긴다
- 공식 서지에서 연도·제1저자 중 한 값이 빠진 부분 식별은 아래 자리표시자 규칙을 따른다.
  확인하지 못한 값은 페이지에 적고, 나중에 확인되면 파일명 변경과 링크 갱신을 같은 작업에서 처리한다
- 연도와 제1저자를 모두 확인하지 못하면 식별 실패로 처리한다. 파일을 만들지 않고
  사용자에게 논문을 식별할 정보를 요청한다. 이 조건은 아래의 서지 미확인 자동
  중단 조건보다 우선한다
- 공식 자료에 연도 또는 제1저자 중 한 값만 존재하지 않으면 파일명의 해당 자리에
  `unknown-year` 또는 `unknown-author`를 쓰고 `needs_review`로 저장한다. 나중에
  값을 확인하면 파일명과 연결된 링크를 같은 작업에서 고친다
- 여러 논문 파일명을 한꺼번에 정정할 때는 파일명과 연결 링크의 전체 변경 목록을
  먼저 제시한다. 사용자 승인 전에는 실제 이름과 링크를 바꾸지 않는다

## 개념 페이지

`concepts/`는 논문을 읽다 반복해서 나오는 개념을 한 페이지에 모아두는 곳이다.
topics/·venues/·years/·authors/와 달리 서지에서 자동으로 파생되지 않으므로 아래
조건을 만족할 때만 만든다.

- 원문에서 확인한 개념만 만든다. 정의는 그 논문 원문이나 개념을 제시한 1차 출처에서
  확인하고, 확인한 위치를 개념 페이지에 적는다. 정의를 확인하지 못하면 페이지를
  만들지 않고 논문 페이지의 `Open questions`에 남긴다
- `summarized` 이상에 도달한 논문 페이지에서만 연결한다. `metadata_only` 페이지와
  부분 식별·추출 실패로 `needs_review`가 된 페이지는 topic 허브와 마찬가지로 개념
  연결도 사람 확인 전까지 보류한다
- 파일명은 개념의 공식 영문 용어를 소문자 하이픈으로 연결한다
  (`domain-adaptation.md`). 비ASCII 문자는 ASCII로 옮긴다. topics/와 같은 관례다
- `concepts/_template.md`를 복사해 만들고, 템플릿에 없는 항목을 새로 만들지 않는다
- 같은 개념 페이지가 이미 있으면 새로 만들지 않고 기존 페이지의 `관련 논문`에
  추가한다. 같은 이름이 분야에 따라 다른 뜻으로 쓰이면 합치지 말고 `needs_review`로
  남긴다
- 링크는 양쪽에 건다. 논문 페이지의 `Related concepts`에서 개념 페이지로, 개념
  페이지의 `관련 논문`에서 논문 페이지로 건다
- `헷갈리는 개념`은 원문에서 저자가 실제로 구분한 경우에만 적는다
- `내 연구에서의 의미`는 사용자가 정하는 자리다. 에이전트는 추정해 채우지 않고
  비워 둔다
- 새로 만든 개념 페이지는 `llm_wiki/index.md`의 `concepts` 절에 등록한다.
  `concepts/`에는 별도 index를 두지 않는다

## 원문 파일

- 사용자가 원문 PDF를 제공하면 `llm_wiki/attachments/`에 논문 페이지와 같은
  파일명 줄기로 복사하고, 페이지의 `source_file`에는 작업공간 루트 기준 상대
  경로를 기록한다
- `llm_wiki/attachments/`가 없으면 첫 원문 PDF를 저장할 때 만든다
- 같은 경로의 PDF가 이미 있으면 내용이 같은지 확인한다. 같으면 기존 파일을
  사용하고, 다르면 덮어쓰지 말고 사용자에게 묻는다
- 완료 보고에는 원문 사본을 저장하거나 기존 사본을 재사용한 경로를 밝힌다
- 서지를 확정하지 못해 논문 페이지를 만들지 않는 경우에도 사용자가 준 원문 PDF는
  버리지 않는다. 페이지 파일명 줄기가 없으므로 `llm_wiki/attachments/_unidentified/`
  아래에 사용자가 준 파일명 그대로 저장한다. 이 폴더도 첫 저장 때 만든다
- 서지가 확정되면 같은 작업에서 사본을 `llm_wiki/attachments/` 아래 페이지 파일명
  줄기로 옮기고 `source_file`을 기록한다. `_unidentified/`에는 남기지 않는다
- `_unidentified/`에 저장한 사본의 경로는 사용자에게 묻는 질문과 완료 보고에 함께
  적는다. 이 저장은 논문 페이지를 만든 것으로 보지 않는다

## 상태 필드

`processing_status`는 이 페이지가 어느 작업 단계까지 진행됐는지를 나타낸다.

- `metadata_only`: 서지정보만 있음
- `summarized`: 원문 기반 Summary를 저장함
- `critically_reviewed`: 핵심 판단의 원문 대조를 통과함
- `needs_review`: 자동 처리를 멈추고 사람의 확인을 기다림

**`evidence_status`는 페이지의 핵심 판단이 원문으로 얼마나 뒷받침되는지를 나타낸다.**
**값과 뜻은 아래 `Critical reading 검증 상태`에 정의한다.**

## 근거 판본

요약과 원문 대조에 실제로 사용한 판본을 `source_edition`에 적고, 본문 Summary 첫 줄에도
어느 판본을 읽었는지 밝힌다. 같은 논문의 arXiv 판과 정식 게재본은 내용이 다를 수 있으므로,
어느 쪽을 읽었는지 밝히지 않은 요약은 검증된 것으로 보지 않는다.

프리프린트를 근거로 요약했다면 다음 단서를 Summary에 단다.

> 이 요약과 검증은 arXiv 판본을 근거로 한다. 정식 게재본과 내용이 다를 수 있다.

정식 게재본을 읽었다면 판본 표기만 남기고 단서는 달지 않는다. 판본을 바꿔 다시 읽었으면
`source_edition`을 갱신하고 검증 상태를 다시 판정한다.

## 두 단계

한 편을 처리하는 일은 두 단계로 나뉜다.

1. 원문 확보와 요약 → `processing_status: summarized`, `evidence_status: unreviewed`
2. 핵심 판단을 원문과 대조 → `processing_status: critically_reviewed`, `evidence_status: verified`

1단계에서 Critical reading을 채우지 않는다. 1단계를 끝낸 페이지만 2단계로 넘긴다.

## Critical reading 검증 상태

Critical reading의 각 핵심 판단에는 원문 위치와 검증 상태를 기록한다.

- `unreviewed`: 원문 대조 검증 전
- `verified`: 표시한 원문 위치가 판단 전체를 직접 뒷받침함
- `partial`: 원문이 판단의 일부만 뒷받침함
- `unsupported`: 표시한 위치에서 판단을 뒷받침할 근거를 찾지 못함
- `needs_review`: 분야 지식이나 연구자의 판단이 추가로 필요함

`unsupported` 항목은 확정 내용에 남기지 않고 검토 목록으로 옮긴다.
이 경우 자동 처리는 완료한 것으로 보고하되, 제외한 판단과 사람 확인이 필요하다는
사실을 함께 밝힌다.

`partial` 항목은 상태만 `verified`로 바꾸지 않는다. 원문이 실제로 뒷받침하는 범위로
판단을 좁힌다.

같은 답을 다시 생성한 것은 원문 대조 검증으로 간주하지 않는다.
검증 상태는 표시한 원문 위치를 다시 확인한 결과이며 모델의 자신감 점수와 무관하다.

## Critical reading 처리 절차

비판적 읽기는 생성과 검증을 분리한다.

1. 1차 분석
   - 핵심 주장
   - 근거와 원문 위치
   - 제한 조건과 약점
   - 재현 가능성
   - 내 연구에 주는 함의

2. 2차 검증
   - 표시한 원문 위치를 다시 확인
   - 각 핵심 판단에 검증 상태 기록
   - `unsupported` 항목 이동
   - `partial` 판단의 범위 조정
   - 페이지 전체 상태 종합

1차 분석 결과를 그대로 검증 완료로 간주하지 않는다.

## 페이지 상태 종합

항목별 검증 결과와 프런트매터의 페이지 상태를 다음처럼 연결한다.

| 상황 | `processing_status` | `evidence_status` |
|---|---|---|
| 서지 확정, 접근 가능한 원문 미확보 | `metadata_only` | `unreviewed` |
| 연도 또는 제1저자 한 값이 공식 자료에 없음 | `needs_review` | `unreviewed` |
| 원문 확보 후 텍스트 추출 실패 | `needs_review` | `needs_review` |
| 요약 완료, 원문 대조 전 | `summarized` | `unreviewed` |
| 핵심 판단이 모두 원문 대조 통과 | `critically_reviewed` | `verified` |
| 핵심 판단이 일부만 뒷받침됨 | `needs_review` | `partial` |
| 핵심 판단의 근거가 확인되지 않음 | `needs_review` | `unsupported` |
| 사람의 분야 판단이 필요함 | `needs_review` | `needs_review` |

`processing_status`는 작업을 계속 자동 진행할 수 있는지를 나타낸다.
`evidence_status`는 페이지의 핵심 판단이 원문으로 얼마나 뒷받침되는지를 나타낸다.
따라서 `processing_status: needs_review`와 `evidence_status: partial`처럼 값이 다른 조합이
가능하다.

페이지 상태는 연구 결론과 후속 분석에 사용할 핵심 판단을 기준으로 종합한다. 주변적인 참고 메모는
상태 종합에서 제외한다. 주변 참고 메모는 `Open questions`로 옮길 수 있다.

## 자동 중단 조건

신규 논문을 외부 서지 DB에서 식별하지 못하면 논문 페이지를 만들지 않고 확인을 요청한다.
DB에 접근하지 못한 경우에는 접근 실패를 밝히고 중지한다. 논문이 DB에 없다고 판정하지 않는다.
사용자가 준 PDF는 「원문 파일」 규칙에 따라 보관한다. 공식 자료에서 한 값만 빠진 부분 식별은
「페이지 형식」의 자리표시자 규칙을 따른다.

이미 있는 페이지나 식별된 논문에서 다음 문제가 발견되면 `processing_status: needs_review`로 멈추고 이유를 기록한다.

- 확보한 원문의 텍스트 추출 실패
- **핵심 판단에 원문 위치가 없음**
- **표시한 원문 위치와 판단이 일치하지 않음**
- **표나 그림을 읽지 못했는데 수치를 단정함**
- **저자가 밝힌 제한과 분석자의 추론이 섞임**
- **분야 기준 없이 "표본이 작다" 같은 일반적인 비판만 생성함**
- **서지를 외부 DB에서 확인하지 못함**
- **기록된 DOI가 해석되지 않음**

서지는 확정했지만 합법적으로 접근 가능한 원문을 확보하지 못한 경우에는 확인된
서지와 실패 사유만 기록하고 `metadata_only / unreviewed`로 멈춘다. 방법, 결과,
수치, 한계와 Critical reading은 추정하지 않는다.

원문에서 확인하지 못한 항목은 추론으로 채우지 않는다.

**원문 대조 자체가 불가능했다면 `evidence_status: needs_review`로 기록한다.**
**대조 결과가 일부만 성립하면 `evidence_status: partial`로 기록한다.**
**근거가 판단을 지지하지 않으면 `evidence_status: unsupported`로 기록한다.**
